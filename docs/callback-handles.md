# 콜백 핸들 (설계 초안)

상태: 초안. 구현하지 않았다. 계약에 넣기 전에 이 문서의 결정 사항을 확정한다.

## 풀려는 문제

스크립트나 샌드박스가 함수를 호스트 쪽에 맡기고, 호스트나 다른 쪽이 나중에 그 함수를 다시 부르고 싶은 경우가 있다. 지금 계약은 이것을 허용하지 않는다. `Value`는 JSON에 64비트 정수와 바이트를 더한 것뿐이고, 함수, 클래스 인스턴스, getter가 있는 객체는 넘기는 자리에서 `TypeError`가 난다([JavaScript 바인딩](bindings/javascript.md)). 이 제한은 유지한다. 함수가 필요하면 함수 자체가 아니라 **핸들**을 넘긴다.

## 원칙

- 함수 본문이나 클래스는 경계를 넘지 않는다. 경계에는 `handle<callback>` 타입의 문자열 `cb-<uuid>`만 오간다.
- 함수는 만든 엔진 안의 레지스트리에 남는다. 반대쪽이 부르려면 호스트를 거쳐 만든 쪽에 요청하고, 만든 쪽 엔진이 자기 스레드에서 실행한다.
- 핸들은 만든 세션과 세대에 묶인다. 세션이 끝나거나 엔진이 다시 시작되면 그 세대의 핸들은 모두 만료된다. 메시지 토큰(`ProviderTokens`)과 같은 규칙이다.

## 모양

스펙에서는 새 타입 `handle<callback>`을 쓴다. 호출은 호스트 모듈 하나로 한다.

| 함수 | 뜻 |
|---|---|
| `callback.invoke({handle, args})` | 핸들이 가리키는 함수를 `args`(`list<any>`)로 부른다. 결과 `Value`를 돌려준다. |
| `callback.release({handle})` | 핸들을 미리 버린다. |

JavaScript 바인딩에서는 키트가 함수를 레지스트리에 넣고 핸들로 바꿔 보내며, 받는 쪽에서는 핸들을 부르면 `invoke`가 되는 함수로 되살린다. 엔진이 하는 일은 함수를 `Value`로 바꾸는 규칙뿐이라서, `JavaScriptEngineConformance`에 케이스를 먼저 넣고 시작한다.

## 규칙

1. **소유**: 핸들은 `(세션, 세대, 만든 쪽)`에 묶인다. 다른 프로젝트나 세션의 핸들로 부르면 `unavailable`이다.
2. **수명**: 세션이 끝나거나 엔진이 죽으면 만료된다. 만료된 핸들 호출은 `unavailable`이고 메시지에 이유를 적는다.
3. **용량**: 세션마다 개수를 제한하고(예: 1024), 넘으면 가장 오래 쓰지 않은 핸들부터 버리지 말고 새 핸들 만들기를 거부한다. 쓰는 중인 핸들을 조용히 버리면 호출이 이유 없이 실패한다.
4. **일회용**: `once`로 만든 핸들은 한 번 부르면 만료된다. 이벤트 응답 같은 경우에 쓴다.
5. **스레드와 데드라인**: 호출은 만든 엔진의 스레드 하나에서만 실행한다. 요청에는 데드라인을 붙이고, 기다리는 쪽이 포기한 뒤에 집힌 요청은 실행하지 않는다(`RpcPeer`와 같은 규칙).
6. **인자와 결과**: 둘 다 `Value`다. 크기와 깊이는 `ValueCodec`의 한도를 따른다.
7. **재진입**: 콜백 안에서 다시 `callback.invoke`를 부르는 것은 허용하되 깊이를 제한한다. 서로 기다리는 교착을 막으려고 같은 스레드에서 이미 기다리는 핸들을 다시 부르면 즉시 실패한다.

## 결정이 필요한 것

- 핸들을 부를 수 있는 쪽: 호스트와 같은 프로젝트의 스크립트만으로 시작할지, 샌드박스와 프로젝트 사이도 열지.
- 핸들 개수 제한과 데드라인 기본값.
- 클래스는 같은 방식으로 풀지 않는다. 상태는 소유자 쪽에 두고 `핸들 + 메서드 이름`으로 부르는 `object` 핸들을 별도로 설계한다.
- 계약에 넣는 시점. 프로토콜이 0인 동안에는 자유롭게 바꿀 수 있지만, 출시 전에 확정해야 한다.
